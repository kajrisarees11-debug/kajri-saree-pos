## Executive summary

This app ships two ways from one codebase: a Vercel/MongoDB web deployment and an Electron/SQLite desktop app, unified by a "universal DB adapter" (`src/lib/dataAdapter.js`) that is supposed to route every read/write to the right backend, plus an offline-first sync layer (`src/lib/syncEngine.js`, `src/lib/offlineSync.js`) that queues offline writes and reconciles them later.

**The single biggest problem in the codebase is that this abstraction is not consistently used.** At least 12 API routes (single-invoice GET, both return endpoints, both payment endpoints, backup, CSV import, both accounting/sales report endpoints, and the invoice offline-sync endpoint) `import` SQLite directly instead of going through the adapter, with **zero check** for which backend is actually active. On the Vercel/MongoDB deployment, `src/lib/sqlite.js` resolves its database file to `/tmp/kajri-pos.db` — an empty, ephemeral, per-instance file that's wiped on every cold start. So on the live web deployment: viewing an invoice's detail page, processing a sales or purchase return, recording a customer or supplier payment, downloading a backup, importing a CSV, and viewing the Sales/Accounting/Balance-Sheet/Trial-Balance reports all either hard-404 or silently read/write an empty database while reporting success. This is almost certainly the root of the "online/offline database" problems you're seeing — it isn't one bug, it's a whole class of routes that never got migrated when the dual-backend adapter was introduced.

On top of that systemic issue, the audit found real data-loss bugs in the sync engine itself (partial sync failures marked as fully synced, non-idempotent stock/balance updates that can double-apply on a crash, downsync that only ever pulls `products` back to the desktop), critical security holes (hardcoded JWT secret and admin PIN fallbacks, `/api/*` routes entirely unprotected by the auth middleware, SQL-identifier injection via unvalidated update keys, a plaintext DB credential committed to source), features that are pure UI facades with **no backend persistence at all** (Bank Accounts and Cash Ledger pages), and several silent-failure logging gaps exactly matching what you flagged — empty `catch` blocks, `console.log`-only error paths in a packaged desktop app with no attached console and no log file.
